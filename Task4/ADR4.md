# Архитектурное Решение и План Развития MVP по Открытию Депозитов

## 1. Архитектурное Решение (ADR)

### **Название задачи:** Расширение MVP: Централизация ставок и поддержка партнёрского кол-центра

### **Автор:** Хайруллин Ринат Растамович

### **Дата:** 03 Декабря 2025

---

### **Функциональные требования**

| **№** | **Действующие лица или системы** | **Use Case** | **Описание** |
| :---: | :--- | :--- | :--- |
| **1** | Сотрудник Кол-центра (внутреннего), СРС | Консультирование по ставкам (API) | Сотрудник запрашивает **Систему кол-центра**, которая вызывает **СРС** для получения актуальных ставок, чтобы проконсультировать клиента. |
| **2** | Сотрудник Партнёрского КЦ | Консультирование по ставкам (Файл) | Сотрудник использует внешнюю систему для получения актуальных ставок из файла, переданного банком по SFTP. |
| **3** | СРС, Сервис Дистрибуции Ставок (СДС) | Генерация и экспорт файла ставок | **СРС** генерирует данные. **СДС** формирует файл с актуальными ставками и передает его по защищенному каналу (SFTP) во внешнюю систему партнера. |
| **4** | Клиент (Существующий), Интернет-банк, СРС | Получение персонализированной ставки | Клиент входит в **Интернет-банк**. Интернет-банк запрашивает **СРС** для отображения актуальных персонализированных ставок. |
| **5** | Менеджер бэк-офиса, АБС, СРС | Обработка и подтверждение заявки | Менеджер бэк-офиса обрабатывает заявку, используя **АБС** и **СРС**. СРС предоставляет единую логику расчета ставки. |

---

### **Нефункциональные требования**

| **№** | **Требование** |
| :---: | :--- |
| **NF.1** | **Надёжность:** Предоставление актуальных ставок должно быть **24/7** и не зависеть от нагрузки на АБС. |
| **NF.2** | **Производительность:** Получение ставок внутренним КЦ должно быть **быстрым** (миллисекунды). |
| **NF.3** | **Интеграция (Файл):** Поддержка **файлового обмена (SFTP)** для передачи актуальных ставок во внешнюю систему партнёрского КЦ. |
| **NF.4** | **Безопасность:** Передача актуальных ставок партнеру должна происходить по **защищенному каналу (SFTP)**. |
| **NF.5** | **Архитектура:** Использовать **централизованный источник ставок (СРС)** для всех каналов (КЦ, Партнёр, ИБ). |
| **NF.6** | **Масштабирование:** Обеспечить **горизонтальное масштабирование** нового функционала. |

**Логика и Обоснование Принятия Решений:**

1.  **Централизация ставок (NF.5):** Создание **Сервиса Расчета Ставок (СРС)** на **Java/Spring Boot** как единого источника актуальных ставок. Это устраняет XLS-файлы и обеспечивает консистентность.
2.  **Интеграция с внутренним КЦ (NF.2):** Система кол-центра напрямую вызывает **API СРС** для быстрого получения данных, минуя АБС.
3.  **Интеграция с Партнёром (NF.3, NF.4):** Создан **Сервис Дистрибуции Ставок (СДС)**, который берет на себя ответственность за выполнение требования о **файловом обмене (SFTP)**. Это изолирует сложную логику внешней интеграции от ядра.
4.  **Разгрузка АБС и Масштабирование (NF.6):** Все новые компоненты (СРС, СДС, API Gateway, СОЗ) разработаны на масштабируемом стеке **Java/Spring Boot**, что гарантирует **горизонтальное масштабирование** и защиту перегруженной АБС от пиковых нагрузок.

### **Альтернативы**

| Альтернативное Решение | Причина Отклонения |
| :--- | :--- |
| **Прямая передача файла из АБС** | **Противоречит NF.5** (Централизация) и стратегии разгрузки АБС. АБС должна выполнять только ядровую функцию. |
| **Разработка API для Партнёра** | **Противоречит ограничению партнёра.** У партнера нет возможности сделать API-вызовы, необходимо использовать файловый обмен. |

### **Недостатки, ограничения, риски**

| Тип | Описание | Пути Снижения Рисков |
| :--- | :--- | :--- |
| **Риск** | **Актуальность данных у Партнёра.** Файловый обмен всегда имеет задержку по сравнению с API. | Обеспечить частый, автоматический экспорт данных (например, каждые 15 минут). В файле указывать таймстемп генерации. |
| **Недостаток** | **Новый компонент (СДС).** Требуется разработка и поддержка нового сервиса, работающего с SFTP. | Использовать готовые библиотеки Java для SFTP, минимизируя сложность. |

## 2. Список крупных задач по системам

| Система / Команда | Крупные Задачи |
| :--- | :--- |
| **Новые Сервисы (Java Team)** | 1. **Разработка Сервиса Расчета Ставок (СРС):** Реализация логики расчета, хранение данных, предоставление API. (**Критично**). |
| | 2. **Разработка Сервиса Дистрибуции Ставок (СДС):** Реализация логики экспорта, формирования файла и безопасной передачи (SFTP) партнеру. |
| | 3. **Разработка API Gateway и Сервиса Оркестрации Заявок (СОЗ):** Реализация интеграционного слоя и асинхронной логики подачи заявок. |

| **Интернет-банк (.NET Team)** | 5. **Интеграция с API Gateway:** Перенастройка Интернет-банка на вызов API Gateway для получения персонализированных ставок и подачи заявок. |
| | 6. **Реализация подтверждения СМС-кодом:** Доработка интерфейса для ввода СМС-кода. |
| **АБС (Delphi/PL-SQL Team)** | 7. **Доработка/Подготовка АБС:** Создание API для получения данных о риске клиенте (для СРС) и обработка финальной команды на открытие депозита от СОЗ. |
